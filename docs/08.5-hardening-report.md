# Phase 8.5 Hardening Report

Дата: 2026-07-23

## Что сделано

- Добавлена freshness-защита signed session handoff: `issuedAt` должен быть unix timestamp, не старше 10 минут и не более чем на 5 минут в будущем.
- Backend error responses и headers получили `requestId`; backend logs пишут тот же `requestId` без CRM payloads и session tokens.
- Основной `backend/.env.example` сделан production-safe: `NODE_ENV=production`, `SESSION_CONTEXT_MODE=signed-headers`, обязательный `SESSION_CONTEXT_HMAC_SECRET`.
- Локальный пример вынесен в `backend/.env.development.example`; `docs/08-local-integration.md` обновлен под development example.
- Денежные KPI переведены на отдельный bounded query `moneyKpi`; если query достигает лимита 500, DTO meta получает `truncatedBlocks: ['moneyKpi']`, а frontend помечает денежные KPI как частичные.
- Frontend requested scopes сокращены до MVP minimum: `user_brief`, `crm`.
- Удалены template routes/pages, demo components, notification slideover, legacy `useDealStats` и direct `crm.item.list` path из production source.
- Production mock mode запрещен: `createDashboardApi` бросает ошибку при `mockMode=true` и production mode.
- Добавлены guard tests для scopes, production surface, direct CRM source path и production mock mode.

## Production Handoff Boundary

- Trusted producer: production gateway/runtime перед backend, который получает Bitrix24/VibeCode session из iframe handoff и подписывает backend-only headers.
- Trusted headers в `SESSION_CONTEXT_MODE=signed-headers`: `X-VibeCode-Session-Token`, `X-VibeCode-Portal-Domain`, `X-VibeCode-User-Id`, `X-VibeCode-Session-Issued-At`, `X-VibeCode-Session-Signature`.
- Signature payload: `sessionToken`, `portalDomain`, `userId`, `issuedAt`, joined with `\n`, signed as `sha256=<hex>` with `SESSION_CONTEXT_HMAC_SECRET`.
- Freshness window: accepted if `issuedAt` is not older than 600 seconds and not more than 300 seconds in the future.
- Untrusted in production: browser-supplied `Authorization`, `X-Bitrix24-Domain`, `X-Bitrix24-User-Id`; these are accepted only in `SESSION_CONTEXT_MODE=provisional-headers` for local/dev use.
- Secret storage: `SESSION_CONTEXT_HMAC_SECRET` must exist only in backend/gateway runtime env, never in frontend env, bundle, localStorage, sessionStorage or logs.

## Оставшиеся риски

- Реальный production handoff producer все еще внешний к текущему repo: нужно подтвердить в Black Hole/VibeCode Gateway, кто подписывает headers/cookies и как доставляется `SESSION_CONTEXT_HMAC_SECRET`.
- `groupBy: currency` подтвержденно не поддержан текущим VibeCode aggregate contract; monetary KPI защищены partial marking, но полные totals для больших воронок потребуют API windowing или нового aggregate contract.
- Build все еще предупреждает о крупном frontend chunk > 500 kB; после удаления template routes размер снизился, но Phase 9 должен решить, является ли это quality gate.
- `dashboard-app/src/route-map.d.ts` является generated typed-route artifact и обновляется tooling при удалении routes; его нельзя править вручную.
