# Концепция приложения «Дашборд воронки продаж»

## 1. Назначение приложения

Приложение встраивается в Битрикс24 и предоставляет руководителю отдела продаж агрегированную аналитику по сделкам CRM.

Основная цель — помочь руководителю быстро оценивать:

- текущее состояние воронки продаж;
- объём открытых и выигранных сделок;
- средний чек;
- динамику продаж за выбранный период;
- распределение сделок по стадиям;
- ответственных сотрудников по сделкам.

## 2. Главный пользователь

Главный пользователь приложения — руководитель отдела продаж.

Приложение должно показывать все сделки, доступные текущему пользователю в соответствии с правами CRM Битрикс24.

Приложение не должно обходить ограничения доступа и не должно показывать сделки, которые пользователь не имеет права просматривать.

## 3. Работа с воронками

В интерфейсе используется переключатель воронки.

По умолчанию выбирается основная воронка портала.

Для аналитики пользователь выбирает одну конкретную воронку. Это необходимо, поскольку разные воронки могут иметь разные наборы и последовательности стадий.

Возможный режим «Все воронки» может использоваться для общих ключевых показателей и списка сделок, но визуализация стадий должна строиться для одной выбранной воронки.

## 4. Период анализа

По умолчанию приложение показывает данные за последние 30 дней.

Базовый фильтр периода работает по дате создания сделки.

После изменения периода должны пересчитываться все элементы дашборда:

- ключевые показатели;
- сводка по стадиям;
- динамическая визуализация воронки;
- график динамики;
- таблица последних сделок.

Фильтр не должен влиять только на таблицу, иначе разные части дашборда будут показывать несогласованные данные.

## 5. Определение состояния сделки

Состояние сделки определяется не по названию стадии, а по системной семантике стадии Битрикс24.

Стадии могут иметь произвольные пользовательские названия. Например, стадия «Подготовка к сдаче проекта» может оставаться рабочей, даже если визуально расположена в конце воронки.

Используются следующие правила:

- открытая сделка — текущая стадия имеет семантику «в работе»;
- выигранная сделка — текущая стадия имеет успешную семантику;
- проигранная сделка — текущая стадия имеет неуспешную семантику.

Таким образом, логика приложения не зависит от текста названия стадии.

## 6. Ключевые показатели

Дашборд должен отображать как минимум:

1. Общую сумму открытых сделок.
2. Количество выигранных сделок за выбранный период.
3. Средний чек выигранной сделки.

Дополнительно рекомендуется показывать сумму выигранных сделок, поскольку она делает показатели количества и среднего чека более понятными.

Средний чек рассчитывается только по выигранным сделкам выбранного периода:

`сумма выигранных сделок / количество выигранных сделок`

Если выигранных сделок нет, средний чек равен нулю.

## 7. Работа с валютами

Сделки в разных валютах нельзя напрямую складывать в одну сумму.

Автоматическая конвертация по внешнему или текущему курсу не используется, поскольку результат может не совпадать с финансовой логикой портала и историческими курсами.

Допустимые варианты отображения:

- показывать суммы отдельно по каждой валюте;
- добавить фильтр по валюте;
- основную валюту показывать крупно, остальные — дополнительными строками.

Для первой версии предпочтительно не объединять разные валюты в одну итоговую сумму.

## 8. Визуализации

### 8.1. Воронка по стадиям

Основная визуализация показывает распределение сделок по стадиям выбранной воронки.

Для каждой стадии отображаются:

- название стадии;
- количество сделок;
- сумма сделок;
- доля от общей выборки.

Визуализация должна динамически перестраиваться после изменения периода, воронки или валюты.

### 8.2. График динамики

Дополнительный график показывает изменение количества сделок во времени.

Рекомендуемые линии:

- созданные сделки;
- выигранные сделки.

Шаг группировки может зависеть от длины выбранного периода: день, неделя или месяц.

## 9. Таблица последних сделок

Приложение должно показывать 10–20 последних сделок выбранной воронки и периода.

Рекомендуемое количество — 15 сделок.

Для каждой сделки отображаются:

- название;
- сумма и валюта;
- стадия;
- ответственный;
- дата создания.

Сделки сортируются по дате создания в порядке убывания.

## 10. Состав интерфейса

Предлагаемая структура страницы:

1. Заголовок дашборда.
2. Фильтр воронки.
3. Фильтр периода.
4. Фильтр валюты.
5. Карточки ключевых показателей.
6. Динамическая визуализация воронки.
7. График созданных и выигранных сделок.
8. Таблица последних сделок.
9. Состояния загрузки, ошибки и отсутствия данных.

## 11. Зафиксированные ограничения первой версии

- приложение работает только с данными, доступными текущему пользователю;
- анализ строится по выбранной воронке;
- базовый период фильтруется по дате создания сделки;
- история переходов сделки между стадиями не анализируется;
- суммы разных валют не объединяются без явного правила конвертации;
- приложение предназначено только для чтения и не изменяет сделки CRM.
