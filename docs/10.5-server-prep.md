## Open Risks

- The current backend production session mode expects signed `x-vibecode-*` handoff headers. VibeCode Infra docs describe Gateway-injected `X-Vibe-*` headers, including `X-Vibe-Authorization: Bearer <session>`. Phase 11/12 must either validate actual runtime headers or add a compatible session reader before user-context API smoke can pass.
- Current `/health` on the public URL is not this backend yet; Phase 11 must verify `deploymentVersion=192c9bb` after deploy.
- `SESSION_CONTEXT_HMAC_SECRET` has no pre-deploy server-side storage in the checked flow; generating and supplying it is an explicit Phase 11 owner action.
- Black Hole hardening may run the service as a non-root user. The selected `/opt/app` layout is compatible with documented hardening, but Phase 11 logs must confirm whether hardening stayed enabled or rolled back.
