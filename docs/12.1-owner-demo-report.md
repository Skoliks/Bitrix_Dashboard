## Dashboard Data Accuracy Update

- Selected pipeline stages are loaded after filter validation, so every
  category receives its own `DEAL_STAGE_<id>` references.
- The backend makes one bounded, selected-category deal snapshot request and
  derives all KPI, funnel, money, trend, and recent-deal values locally. This
  avoids the upstream final-day date-filter defect and prevents process deals
  with planned close dates from being counted as successful.
- Trend periods are zero-filled and the frontend renders created and successful
  values as grouped bars. Decimal and hexadecimal numeric currency entities,
  including the ruble symbol, are decoded before rendering.
- Changed files: `backend/src/services/referenceDataService.ts`,
  `backend/src/http/routes/dashboard.ts`,
  `backend/src/services/dealsQueryService.ts`,
  `backend/src/services/aggregationService.ts`, their backend tests,
  `dashboard-app/src/components/dashboard/TrendChart.vue`,
  `dashboard-app/src/components/dashboard/dashboardFormatters.ts`, related
  frontend tests, `docs/12.1-owner-demo-report.md`, and `docs/06-plan.md`.
- Checks: 107 backend tests, backend typecheck and lint, production build,
  artifact check, 42 frontend tests, frontend typecheck and lint, and secret
  scan passed. The 71-entry deployment archive had zero forbidden entries.

## Remaining Risks

- This profile is intentionally single-owner and must never be made public or
  used as client delivery.
- It does not complete Phase 12 placement, per-user CRM rights, or restricted
  user acceptance.
- The personal API key was previously shared in chat and must be rotated
  before long-term use.
- The frontend still emits the existing large-chunk build warning.
- A selected-category snapshot is capped at 500 deals. At that limit the API
  returns `PARTIAL_AGGREGATION` with `truncatedBlocks: ['snapshot']`; values
  should be treated as partial until pagination is introduced.
