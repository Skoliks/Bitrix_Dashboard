# Дашборд воронки продаж для Bitrix24

Read-only приложение для аналитики сделок CRM Bitrix24.

## Что показывает

- количество и суммы сделок по стадиям воронки;
- общую сумму открытых сделок;
- количество выигранных сделок за выбранный период и средний чек;
- последние 15 сделок с названием, суммой, стадией и ответственным;
- динамику сделок и фильтр периода.

## Права

- `crm` — чтение сделок и стадий CRM;
- `user_brief` — отображение ответственных;
- `placement` — размещение приложения в интерфейсе Bitrix24.

Приложение не создаёт, не изменяет и не удаляет записи CRM.

## Структура

- `dashboard-app/` — Vue 3 frontend;
- `backend/` — Node.js BFF, который получает CRM-данные и отдаёт готовую аналитику;
- `scripts/` — проверки production-артефакта, секретов и лицензий.

## Ограничения

- Аналитика строится по выборке до 500 сделок; при большем объёме результат помечается как неполный.
- Для отдельного портала Bitrix24 требуется повторить деплой и публикацию OAuth-приложения в его VibeCode-аккаунте.
- Секреты в репозитории не хранятся.

## Публичное демо

После включения владельцем сервера политики «Публично» демонстрационная версия доступна по адресу:

`https://app-6a13554216e2.vibecode.bitrix24.tech/demo`

Страница показывает только встроенную тестовую воронку и тестовые сделки. Она не обращается к CRM, не использует ключи и не раскрывает данные портала. Рабочий дашборд открывается из пункта левого меню Bitrix24 и в этом контексте показывает данные, доступные текущему пользователю.

## Как проверить

1. Открыть публичное демо по ссылке выше и убедиться, что видны пять стадий, сделки и график «Выиграно».
2. В подключённом Bitrix24 открыть «Дашборд воронки продаж» из левого меню пользователем с правом чтения CRM.
3. Проверить фильтры, последние сделки и открытие карточки сделки. Пользователь должен видеть только данные, доступные ему в CRM.

## Воспроизводимый деплой через VibeCode

1. Получить исходный код без `.env` и установить зависимости: `pnpm --dir dashboard-app install --frozen-lockfile` и `pnpm --dir backend install --frozen-lockfile`.
2. Собрать единый артефакт: `pnpm --dir backend run build:production`.
3. Создать Black Hole сервер в VibeCode и развернуть allowlist-архив с `backend/dist`, `backend/package.json`, `backend/pnpm-lock.yaml` и `dashboard-app/dist`; команда запуска — `node dist/index.js`.
4. Задать значения переменных из `backend/.env.example` только в секретах окружения сервера. Ключи `vibe_api_…`, `vibe_app_…` и токены не добавлять в архив, README или frontend.
5. В VibeCode создать OAuth-приложение, указать HTTPS-адрес сервера, авторизовать его владельцем портала и опубликовать placement `LEFT_MENU` со скоупами `crm`, `user_brief`, `placement`.
6. Проверить `/health`, `/ready`, затем `/demo`. Для проверки живых данных открыть приложение из левого меню пользователем с правом чтения CRM.

## Локальная проверка

Требуются Node.js 20+ и pnpm 10+.

```powershell
cd backend
pnpm install --frozen-lockfile
pnpm run build:production
pnpm run test
pnpm run security:scan
```

Для frontend-проверок:

```powershell
cd dashboard-app
pnpm install --frozen-lockfile
pnpm run lint
pnpm run typecheck
pnpm run test
```
